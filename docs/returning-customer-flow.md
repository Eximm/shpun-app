# Возвращение клиента и акционный Flex

Возвращающиеся аккаунты не перенаправляются в мастер заказа автоматически. Автоматический вход в мастер допустим только для нового аккаунта младше суток, без истории услуг и доступных акций; ошибка проверки оставляет клиента на главной. Кэш старого решения `assistant` больше не используется.

После принятия или закрытия бонусного предложения другие бонусные окна и автоматические напоминания профиля/push не перебивают тот же сеанс. Ручной ввод промокода участвует в общей очереди окон. Экраны оплаты, заказа и настройки исключены из автоматического показа глобальных предложений.

Состояние RETURN15 берётся из сохранённого состояния SHM отдельным read-only действием `promo.return.status`. API передаёт только явные флаги, идентификатор выданной услуги и параметры акции. Услуги дают фактический статус, дату окончания, следующий тариф и автопродление. Активированная услуга остаётся привязана к своему ID, а после смены service_id на обычный тариф больше не называется акционной.

На главной и в мастере акционный тариф показывается карточкой с кнопкой настройки. Указаны дата перехода, цена следующего тарифа и текущий баланс. Гарантия оплаты не даётся: достаточность проверяется по текущим деньгам, будущие расходы могут её изменить. Скидка и доступные бонусы учитываются по флагам следующего тарифа; неизвестные лимиты бонусов не используются для обещания достаточности. При неизвестных цене или условиях показывается предложение проверить продление в карточке услуги.

Перед заказом мастер повторно читает услуги и акции. API независимо блокирует заказ из мастера при существующей основной услуге, ожидающем бонусе или доступной возвратной акции. Ожидающая возвратная акция и дублирование следующего платного тарифа при уже выданной акции блокируются и для старых вкладок, которые ещё не отправляют флаг мастера. Отсутствие новой billing-проекции останавливает создание заказа до восстановления проверки.

Развёртывание: сначала проверить и установить фрагмент `deploy/billing/return-bonus-status.tt` штатным помощником `apply-return-bonus-status.pl` в контейнере SHM. Он компилирует весь шаблон и проверяет выдачу для восстановленного аккаунта, затем сохраняет резервную копию перед точечной вставкой. После этого обновить API и web через Git/Docker. Полный billing-шаблон и клиентские реквизиты в Git не сохраняются.
