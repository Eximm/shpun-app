# SHM 3.x: стенд и preflight

Этот runbook выполняется до любых изменений `core.shpyn.online`. Стенд использует копию production-БД и отдельную копию `shm-data`; webhook, платёжные callback и исходящая рассылка на стенде отключаются.

## 1. Проверка выбранного исходника

Клонировать официальный SHM и переключиться на точный тег-кандидат. Затем из репозитория ShpunApp выполнить:

```powershell
npm run audit:shm3 -- C:\path\to\shm
```

Код возврата:

- `0` — критичные контракты прошли; предупреждения компенсированы ShpunApp.
- `2` — найден критичный блокер, production-миграция запрещена.
- `3` — указан неполный или неправильный исходник.

Для `3.0.47` ожидается один критичный FAIL: `telegram_session_schema`. Реальные сессии SHM являются 32-символьными строками, а Telegram routes объявляют `session_id` как integer. `password_reset_persists` должен проходить.

## 2. Изоляция стенда

- Отдельные Docker project name, сеть, volumes и порты.
- Никакого доступа со стенда к production MySQL/Redis.
- Отдельный hostname, недоступный поисковым роботам.
- Платёжные callback направлены в заглушку или отключены.
- Telegram webhook не регистрируется.
- SMTP и другие исходящие уведомления перенаправлены в тестовый приёмник.
- OAuth callback регистрируется только для стендового hostname.

## 3. Восстановление

1. Снять согласованный snapshot MySQL и `shm-data`.
2. Восстановить оба компонента в изолированные volumes.
3. Зафиксировать исходные количества пользователей, accounts, услуг, платежей и списаний.
4. Запустить точные образы кандидата по tag и digest, не `latest`.
5. Дождаться миграций и сохранить их полный лог.

## 4. Обязательные проверки

| Блок | Положительный сценарий | Отрицательный сценарий | Доказательство |
|---|---|---|---|
| Пароль | вход старым паролем, смена, reset и вход новым | неверный старый пароль, повтор reset-token | HTTP и повторный вход |
| Email | add, send code, verify, delete | чужой/неверный email и код | accounts до/после |
| Telegram | login, register, bind | занятый Telegram и неверная подпись | account type `telegram` |
| OAuth | Yandex login/register/bind | state replay, конфликт email, cancel | accounts и отсутствие session в URL |
| Профиль | имя и телефон через `profile.set` | пустое и превышение лимитов | повторный GET `/user` |
| Услуги | список, заказ, смена, stop | запрещённый тариф | услуга и списание |
| Платежи | systems, forecast, test callback | повтор callback | платёж и идемпотентность |
| Template | все используемые actions | неверная сессия/параметры | JSON `ok`, readback |

HTTP 200 без проверки тела и сохранённого состояния не считается успехом.

## 5. Критерии допуска

Production допускается только если:

- preflight не имеет critical FAIL;
- контрольные количества после миграции совпали;
- password reset действительно меняет пароль;
- Telegram bind создаёт account типа `telegram`;
- ShpunApp проходит smoke-матрицу с выключенным, затем по одному включённым OAuth-провайдером;
- полный backup MySQL + `shm-data` был восстановлен в чистый стенд;
- подготовлен rollback на точные digest SHM 2.x.

До выполнения этих условий `core.shpyn.online` остаётся на SHM 2.x.
