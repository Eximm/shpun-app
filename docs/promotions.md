# Акции и персональные бонусы

Биллинг определяет доступность и финансовые условия; приложение добавляет настройку показа и локальное состояние отзывов. Включённый показ сам по себе не делает акцию доступной клиенту.

Бонусы — отдельные единицы без валюты. Их количество отображается обычным числом в уведомлениях, промокодах, отзывах и админке. Денежный баланс продолжает отображаться с валютой; переключатель валют и финансовый пересчёт этой правкой не вводятся.

## Управление

- **Админка → Акции:** обновление из биллинга, показ и порядок трёх поддерживаемых механик. «Активна в биллинге» относится к самой механике, а не к доступности для аккаунта администратора.
- **«Описание для клиента» в карточке акции:** необязательный текст до 280 символов. Он отображается в клиентском уведомлении вместе с автоматически полученными условиями. Пустой текст возвращает стандартный вид. Описание не влияет на доступность и начисления; оно относится к механике и сохраняется при замене возвратного кода. Разметка и HTML не исполняются.
- **Биллинг → Промокоды:** отключение, срок, количество применений и условия возвратного кода. Сканер выбирает доступный корневой код с шаблоном `promo_return15`; при нескольких кодах выбирается самый новый доступный. Строки использования исключаются штатным фильтром SHM `isNull`. Если доступных нет, показывается статус последнего найденного кода; клиенты предложения не получают.
- **Замена возвратного кода:** новый код с существующим шаблоном `promo_return15` подхватывается автоматически. Один стабильный переключатель «Возврат» управляет показом этой механики, независимо от названия кода. Для получения обновлённых данных откройте приложение заново или нажмите обновление каталога.
- **Админка → Отзывы:** сумма и переключатель самой бонусной акции. Выключение завершает новые предложения; ранее отправленные отзывы сохраняют обещанную награду. Скрытие карточки в «Акциях» только убирает уведомление, сама награда остаётся доступной.
- **Партнёрские ссылки:** процент первого пополнения по-прежнему задаётся в настройке конкретной ссылки. Код возврата и FirstPay взаимно исключаются при активации, а обработчики начислений остаются независимыми.

## Персональный отбор

Возвратный код предлагается только при `active=1`, `eligible=1`, без использованного или ожидающего возвратного бонуса и без ожидающего FirstPay. Биллинг проверяет активные/переходные услуги, архивные даты завершения и дату регистрации для аккаунтов без истории услуг. При применении условия повторяются до вызова `promo.apply`, поскольку SHM фиксирует использование раньше выполнения прикреплённого шаблона.

Первое положительное пополнение после активации выдаёт обещанные 15% и 7 дней Flex через существующий платёжный обработчик. Отключение или удаление исходного кода останавливает новые активации. Уже активированный бонус сохраняется, и приложение показывает напоминание о пополнении из сохранённого состояния аккаунта.

Бонус за отзыв предлагается только при активной акции и отсутствии уже отправленного/опубликованного или оплаченного отзыва. Скрытый оплаченный отзыв не открывает повторную награду. Отклонённый неоплаченный отзыв допускает исправленную отправку.

При отправке отзыва сервер проверяет биллинг и сохраняет `reward_offer_status` и `reward_offer_amount`. Если биллинг недоступен, отправка возвращает 503; текст в форме сохраняется, и пользователь может повторить попытку. Сумма из тела клиентского запроса не используется. При одобрении начисляется сохранённая сумма, в том числе после завершения акции. Старые ожидающие отзывы без снимка сохраняют прежнее право на бонус; для них при первом одобрении фиксируется текущая настроенная сумма. Отзывы, отправленные при выключенной акции, публикуются без начисления.

## Контракт и обновление

`promo.opportunities.status` возвращает:

```json
{
  "ok": 1,
  "return_offer": {
    "code": "RETURN15", "exists": 1, "active": 1,
    "status_reason": "active", "eligible": 0,
    "pending": 0, "applied": 1, "percent": 15,
    "inactive_days": 30, "tariff_days": 7, "reason": "already_applied"
  },
  "first_pay": { "pending": 0, "percent": 0, "campaign": "" },
  "review_reward": { "active": 1, "amount": 50 },
  "review_reward_amount": 50
}
```

Скалярное `review_reward_amount` сохраняется для старых версий приложения. Новая версия требует явных флагов активности и при неизвестном состоянии не предлагает бонус. Сначала обновляется шаблон биллинга, затем API и web. Миграция SQLite добавляет nullable-колонки без переписывания старых отзывов.

`admin.settings.get/set` поддерживает `reviewRewardEnabled` (`0/1` в ответе). `admin.review.reward` принимает необязательный `amount` только после проверки роли администратора, чтобы выполнять ранее обещанные награды; диапазон 1–500 и существующая защита от повторного начисления сохранены. Сохранение одной суммы старым приложением продолжает работать.

Новые промокоды с другой финансовой механикой автоматически не рекламируются: сначала нужен проверенный read-only адаптер доступности и соответствующий тип действия. Возвратный код с существующим шаблоном можно заменять в биллинге без изменения приложения. Каталог представляет поддерживаемые механики, а не весь произвольный список SHM-шаблонов.

## Проверки

API: `npm run build`, `npm run test:promo`, `npm run test:reviews`. Web: TypeScript, `npm run check:i18n`, `npm run check:hardcoded`, `vite build`. Биллинг: изолированные тесты отключения/удаления/истечения/исчерпания кода, замены кода, первого платежа, конфликта FirstPay, завершения отзывной акции и повторного начисления.
