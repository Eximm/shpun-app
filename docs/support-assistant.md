# База сценариев поддержки

## Встраивание

Модуль: `api/src/modules/support`. Существующие `routes.ts` и `internalRoutes.ts`
обслуживают кабинет и Telegram; `service.ts` управляет перепиской и статусами,
`sqliteRepository.ts` хранит тикеты. `snapshot.ts` через `SupportShmPort` получает
личность пользователя и снимок принадлежащей ему услуги. До этого изменения
автоответчика, модели ИИ и API диагностики в модуле не было.

`knowledge.json` — версионированные 20 сценариев. В каждом: группы триггеров,
ссылки на словарь внутренних проверок, простой первый ответ, следующие шаги,
условия передачи оператору. Триггеры: AND между группами, OR внутри группы;
регистр, пробелы и ё нормализуются. Это поиск кандидатов, не диагностика.

`assistant.ts` подключён к существующему защищённому API:

`GET /api/admin/support/tickets/:id/assistant`

Пример: «Windows Happ подключается, но нет интернета» → `windows_happ_tun`.
«Уже пробовал, не помогло» → `repeat_failure` с рекомендацией оператора.
Последнее видимое сообщение пользователя определяет кандидатов; устаревшие
сообщения, удалённые сообщения и внутренние заметки не запускают ответ.
После ответа сотрудника, для закрытого тикета и для партнёрского обращения
подсказок нет. До трёх кандидатов возвращаются с текстом ответа и проверками.
При неизвестном запросе или явной просьбе о специалисте `needsOperator=true`.

Режим — подсказки сотруднику (`staff_suggestion`, `autoSend=false`). API не
отправляет сообщения и не выполняет переходы статусов, переносы или сбросы.
Условия эскалации являются инструкциями сотруднику, а не автоматически
проверенными фактами. Поле `needsOperator` — рекомендация, не факт назначения.
В интерфейс кабинета кнопка подсказок пока не добавлена; API может использовать
будущий авто-помощник. Существующий путь ответа сотрудника сохранён.

## Недостающие данные и ограничения

* Снимок услуги содержит имя, категорию, статус и срок на момент создания
  обращения. Он не является актуальной проверкой аккаунта.
* В `SupportShmPort` нет чтения устройств Remnawave, лимита, online/last seen,
  факта скачивания подписки и проверки реального соединения.
* Нет связи инцидентов мониторинга с массовой ошибкой выдачи подписок.
* Нет API переноса срока Amnezia → Flex, подтверждённой политики прекращения
  поддержки, правил расчёта остатка и доступности Hysteria2 для услуги.
* Нет автоматического чтения изображений и состояния «перенос/отзыв уже
  предлагали». Историю должен проверить сотрудник; автоматическая отправка
  потребует сохранённого состояния диалога, свежих проверок и обработки
  подтверждений. Нельзя отправлять один и тот же шаблон на каждом сообщении.
* Нет проверенной актуальной таблицы приложений/регионов App Store.

Все внутренние проверки возвращаются как `unverified`. Помощник не заявляет,
что сервер исправен по одному успешному импорту или записи устройства.
Переустановка — поздний шаг, не обязательное начало каждого Windows-кейса.
При известном сбое нельзя гонять клиента по локальным переустановкам.
Тарифы, остановка поддержки, переносы и альтернативы не выдумываются.

Источник: доступные последние пять пар сообщений чата
`6aaf910f-fd6c-83eb-befc-17d1350b45f2` и явный перечень кейсов в задании.
API истории не вернул более ранние сообщения; это не полный экспорт чата.

## Проверка

Из `api`: `npm run test:support` и
`node node_modules/typescript/bin/tsc -p tsconfig.json --noEmit`.
Тесты проверяют разделение импорта/соединения, приоритет оператора, исключение
старых и скрытых сообщений, отсутствие изменений тикета и доступ 401/403.
